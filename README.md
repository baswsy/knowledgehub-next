# 知学 KnowledgeHub

## 为什么做知学

学生的课程资料往往分散在讲义、笔记和视频收藏中。资料越来越多，并不等于能够在复习时快速找到依据、理解概念并安排下一步学习。

因此，我将初版通用知识管理工具收敛到课程复习场景，设计了以下路径：

**导入课程资料 → 选择学习范围 → 带来源提问与核对 → 整理知识结构 → 形成自测与复习行动**

产品优先解决“资料能否被找到和正确使用”，再扩展图谱、大纲与视频内容整理。

## 从初版到 LangChain Agent

**初版：验证知识管理的产品形态。**  
借助 CodeBuddy 完成网站，探索笔记、问答、图谱、大纲和收藏入口如何组织，形成可展示的产品界面。

**迭代版：把功能入口连接到可追溯的工具流程。**  
保留独立网页作为主要演示界面，采用 Python + LangChain Agent + MCP 实现后端编排。Agent 可以检索资料、读取原文核对上下文，再组织带来源的回答；用户明确授权后，才允许保存学习笔记。

检索层使用 Chroma 与本地中文嵌入，保留资料来源和段落标识。执行层记录工具调用、异常与预算状态，便于定位问题和复盘。

## 几个关键产品取舍

**让答案可以回到原文。**  
检索结果保留来源与段落，提供原文读取工具；资料不足时应说明缺口。引用校验只能证明出处存在，回答是否准确仍需核对。

**让用户决定资料范围与保存行为。**  
用户选择本次使用的资料，检索和原文读取受同一范围限制。学习偏好用于提供上下文，保存笔记需要单独授权。

**为多轮工具调用设置成本边界。**  
限制调用次数、上下文和累计预算，接近预算上限时停止扩展工具调用，保留已取得的证据。区分模型返回的实际用量与估算值。

**先保证内容可用，再扩大输入范围。**  
PDF 文字层解析不依赖模型；扫描件暂不做 OCR。视频收藏与字幕正文分开处理，未取得字幕时不把标题、简介当作视频内容。

| --- | --- |
| 资料与笔记 | 浏览器本地笔记管理、导入与导出；本地版本支持 PDF 文字层解析，无自动 OCR |
| 学习对话 | 已实现 LangChain + MCP 检索与原文读取链路、来源展示、学习偏好和保存授权；需连接后端与模型 |
| 知识图谱与大纲 | 提供生成接口和成果展示入口；当前独立网页图谱真实生成仍待复验，Figma 展示为原型示例 |
| 视频收藏 | 支持收藏管理及字幕读取、上传入口；公开字幕获取受平台限制，示例 B 站视频尚未取得字幕正文 |
| 执行过程与预算 | 提供工具执行记录与预算信息，辅助观察 Agent 的行为和失败环节 |

当前为单工作区作品演示，尚未提供多用户隔离或云端同步。自动测试、原型效果与真实模型运行分别验证，不将接口实现或测试通过等同于全部场景可用。
